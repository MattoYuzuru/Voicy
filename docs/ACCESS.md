# Как узнать Telegram ID и добавить пользователя

Рабочая копия на VPS: `/opt/voicey`, SSH-алиас `keykomi`. Инструкция для владельца
и будущего AI-агента. Токен и реальные ID сюда не записываются.

1. Новый пользователь открывает **личный чат именно с вашим ботом** и отправляет
   `/start` или `/id`. При отказе бот пишет «Твой Telegram ID: …»; пользователь
   передаёт число владельцу. У разрешённого пользователя `/id` тоже показывает ID.
   Нужен user ID отправителя, а не ID бота, username или номер телефона. Если у
   человека несколько Telegram-аккаунтов, проверять нужно аккаунт отправителя.
2. Владелец подтверждает, кому дать доступ. На сервере выполнить
   `sudoedit /opt/voicey/.env` и добавить число в существующую строку:

   ```dotenv
   ALLOWED_USER_IDS=123456789,987654321
   PUBLIC_BOT=false
   ```

   Это вымышленные примеры: сохранить существующие ID, разделять запятыми, не
   создавать дубликат переменной. Не выводить `.env` целиком и не отправлять токен
   в чат. Доступ разрешает использовать настроенные оператором API-ключи тоже.
3. Дождаться завершения текущих заданий (в приватной SQLite нет queued/running;
   в `docker top voicey-bot-1` нет whisper-cli/llama-server). Затем:

   ```sh
   cd /opt/voicey
   sudo chmod 600 .env
   sudo docker compose up -d --no-deps --force-recreate bot
   sudo docker compose ps bot
   sudo docker compose logs --since=1m --tail=20 bot
   ```

   Пересоздание загружает новые значения `.env`; обычный `restart` этого не делает.
   Не запускать второй poller. Данные, словарь и настройки остаются в `data/`.
4. Новый пользователь повторяет `/start`: вместо отказа должна появиться справка.
   `/id` показывает ожидаемый user ID; чужой пользователь продолжает получать отказ.

Чтобы отозвать доступ, убрать только нужное число и так же пересоздать `bot`.
Профили, словарь и результаты разных пользователей изолированы по user ID.
Лимиты ресурсов и очередь общие: добавление пользователей не добавляет worker.

Если отвечает «Нет доступа», сверить число из ответа с allowlist, проверить
другой Telegram-аккаунт и убедиться, что контейнер пересоздан после изменения.
`access_denied` в логах содержит ID и тип чата, без текста сообщений.
